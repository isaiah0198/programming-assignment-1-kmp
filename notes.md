What kept tripping me up was understanding when the text index i should advance and when it should remain on the same character. In my first version of kmpSearch, I incremented i even after a mismatch where j > 0. I caught this while reasoning through the algorithm rather than from a failed test. The problem is that KMP is supposed to use j = lps[j - 1] to try a shorter valid prefix against the same text character. Advancing i at that point could skip a character that still needs to be compared and potentially miss a valid match. I also initially tried to modify the LPS array during the search, which helped me realise that the LPS table should be built once beforehand and then treated as read-only during matching.
